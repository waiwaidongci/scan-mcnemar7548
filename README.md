# 票据扫描双引擎配对验收

同一张票据交给两套引擎，逐单核对通过结果和切换门槛。

澄石零售财务共享组服务 18 家门店，正在验收报销票据扫描引擎的候选版本。 扫描岗把同一份脱敏影像交给现用引擎 A 和候选引擎 B。质检员对照人工底单核对票号、日期和金额，三项全对才记为通过。导入按票据对齐的结果后，分析员核对配对差异及验收门槛，复核员追查候选引擎掉单，最后把验收结论和票据编号交给财务变更负责人。

- 两份通过率报表无法确认候选引擎补上了哪些票，又丢掉了哪些票。
- 人工合并清单时，重复票据和单边缺测容易误入统计。
- 显著差异和上线所需的最低通过率净增需要分别核对。

## 业务模块

| 模块 | 用途 |
|---|---|
| 验收总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 配对明细 | 下载「澄石票据双引擎配对_20261121.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 运行验收 | 选择批次和参数并提交后台计算，可从运行列表追踪状态。 |
| 验收结果 | 查看业务指标、证据表和解释，通过来源链接回查数据。 |
| 差异复核 | 查看待处理或已完成记录。复核主管可提交差异复核及依据。 |
| 报告交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 演示流程

1. 11 月 21 日 09:00，扫描岗用同一批 64 张脱敏票据并行跑两套引擎，再按人工底单判定通过或未通过。
2. 09:20，在配对明细导入「澄石票据双引擎配对_20261121.csv」，核对两个扫描批次及唯一票据编号。
3. 09:30，在运行验收设置 30 对、α=0.05、净增 5 个百分点，提交运行。
4. 在验收结果确认仅 A 通过 3 对、仅 B 通过 15 对，B 比 A 净增 18.75 个百分点。
5. 在差异复核优先追查 CS-20261121-001 至 003，核对 B 未通过的字段和原始影像。
6. 将净增门槛提高到 20 个百分点重跑，确认显著性门槛仍达标，净增门槛改为未达标。
7. 在报告交付导出采用原门槛的运行结果，把 CSV 和复核记录交给财务变更负责人。

## 计算口径

- 以唯一票据编号配对，每张票据只计一次。两引擎均须提供二元判定，缺测或重复需退回修正。
- 配对表以现用 A 为行、候选 B 为列。记 b 为仅 A 通过、c 为仅 B 通过，差异对数为 b+c。
- 原假设为两引擎边际通过率相同。给定 d=b+c，双侧精确 p 值为 min(1, 2×P[X≤min(b,c)])，其中 X~Binom(d, 0.5)。无差异对时 p=1。
- B 相对 A 的净增为 100×(c−b)/有效配对数，单位为百分点。有效配对数达到下限、p≤α、B 净增达到下限且方向为正时，判定达到统计验收门槛。
- 未达到显著性门槛时，当前数据不足以确认通过率存在差异。达标结论仍需与逐单复核结果一同交付。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | PostgreSQL 16 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
